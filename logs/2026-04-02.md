## 🚀 Project Update - Autonomous Logistics Robot (AGV)

**Date:** 2026-04-02

**Progress:**
We successfully completed the initial integration of the navigation stack for the AGV prototype. The robot can now map its environment using SLAM and navigate autonomously between defined waypoints. Basic obstacle avoidance using the LiDAR sensor and local costmap is functional.

**Technical Work:**
- **ROS Integration:** Implemented the navigation stack on ROS Noetic. The base platform uses a Raspberry Pi 4 running Ubuntu Server 20.04.
- **Odometry & Localization:** Fused data from wheel encoders and the IMU (BNO055) using `robot_localization` package (EKF node) to provide accurate pose estimation.
- **SLAM Implementation:** Configured `gmapping` to generate a 2D occupancy grid map in real-time using data from the RPLiDAR A1 sensor.
- **Path Planning:** Configured `move_base` with a global planner (Dijkstra) and a local planner (DWA) to handle path calculation and dynamic obstacle avoidance.

**Issues & Fixes:**
- **Localization Drift:** Initial testing showed significant localization drift (up to 20cm after 5 meters of travel) when relying solely on wheel odometry due to wheel slippage on the polished floor.
- **Fix:** Implemented the Extended Kalman Filter (EKF) in `robot_localization` to fuse IMU data. The IMU's angular velocity and linear acceleration measurements now compensate for wheel slippage, dramatically improving position accuracy.

**Next Steps:**
- Fine-tune the PID control loops on the motor driver to optimize motion smoothness and reduce overshoot during turns.
- Integrate the depth camera (Intel Realsense D435i) for improved local obstacle avoidance and object detection.
- Develop a mission control interface (web-based) to manage waypoint assignments.

## 🚀 Project Update - IoT Environmental Sensor Node (Project DeepSleep)

**Date:** 2026-04-02

**Progress:**
Completed hardware validation and initial power consumption testing for the remote sensor node. The prototype successfully collects data (temperature, humidity, pressure) and transmits it to the cloud platform (AWS IoT Core) before entering deep sleep mode.

**Technical Work:**
- **Microcontroller & Sensors:** Used the ESP32-S2 module for its low power consumption capabilities. Integrated a BME280 sensor via I2C for environmental data collection.
- **Deep Sleep Optimization:** Implemented a timer wake-up mechanism to trigger data collection every 15 minutes. The code minimizes active time by performing sensor reading and data transmission as quickly as possible (less than 5 seconds) before re-entering deep sleep.
- **Power Monitoring:** Measured power consumption using a dedicated power analyzer (Joulescope) across all states: active transmission (~120mA), active sensor reading (~40mA), and deep sleep mode (<100µA).

**Issues & Fixes:**
- **Excessive Power Draw in Sleep:** Initial deep sleep current draw was significantly higher than expected (around 1.5mA). Investigation revealed that the I2C pull-up resistors on the BME280 breakout board were constantly drawing current, even when the ESP32 was asleep.
- **Fix:** Modified the hardware by adding a low-side MOSFET switch to completely cut power to the BME280 sensor and its pull-up resistors when the ESP32 enters deep sleep. This reduced the overall sleep current to the target level.

**Next Steps:**
- Design a custom PCB layout incorporating these power-saving optimizations.
- Implement over-the-air (OTA) update functionality for remote firmware upgrades.
- Begin long-term battery life testing using a 3.7V LiPo battery.

## 🚀 Project Update - Vision-Based Quality Control System (Project AI-QC)

**Date:** 2026-04-02

**Progress:**
We successfully trained and evaluated the initial object detection model (YOLOv5s) for defect identification on the assembly line. The model achieved promising results in identifying missing components and misaligned labels on test data.

**Technical Work:**
- **Model Training:** Used transfer learning with a pre-trained YOLOv5s model. Fine-tuned on a custom dataset of approximately 4,000 images, including both healthy and defective parts.
- **Data Augmentation:** Applied aggressive data augmentation techniques (random rotation, brightness adjustments, and perspective shifts) to improve model robustness against real-world lighting variations and part positioning errors on the conveyor belt.
- **Evaluation Metrics:** Achieved a Mean Average Precision (mAP) of 0.84 at IoU 0.5 for defect classification. Precision on critical defects exceeded 0.90.

**Issues & Fixes:**
- **False Positives:** The initial training run showed a high rate of false positives on healthy parts (misclassifying slight variations in lighting as defects). The model overfitted to specific lighting artifacts present in the initial dataset.
- **Fix:** Implemented a new data curation strategy where we specifically sourced images from multiple camera angles and lighting conditions. Retrained the model with a more diverse dataset, significantly reducing false positives without compromising true positive rates.

**Next Steps:**
- Optimize model for edge deployment on the Jetson Nano (conversion to ONNX/TensorRT) to reduce inference latency below 50ms per frame.
- Develop the user interface for human-in-the-loop validation of identified defects.
- Begin integration testing on the physical test rig with live camera feed.
