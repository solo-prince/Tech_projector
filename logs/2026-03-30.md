## 🚀 Project Update - Ares Rover Platform

**Date:** 2026-03-30

**Progress:**
- Completed initial integration and testing of the motor control system and ultrasonic sensor array.
- Successfully implemented basic open-loop movement commands (forward, reverse, turn left/right).
- Established serial communication between the main Arduino Mega controller and a secondary Raspberry Pi 4 for high-level command interpretation.

**Technical Work:**
- **Motor Control:** Refactored the motor control code to implement a basic PID loop for each of the four drive motors, replacing the previous simple PWM control. This significantly improved straight-line tracking accuracy by compensating for varying motor friction and battery voltage changes.
- **Sensor Integration:** Finalized the mounting and wiring for the 5-sensor ultrasonic array (HC-SR04). Wrote initial code to handle sensor input, implementing a median filter to reduce noise and spurious readings.
- **Firmware Structure:** Modularized the firmware into separate libraries for motor control (`Motor_Driver.h`), sensor reading (`Sensor_Array.h`), and command processing (`Command_Parser.h`), improving code maintainability.

**Issues & Fixes:**
- **Issue:** The L298N motor drivers were overheating significantly during sustained operation at full power. This caused intermittent motor cutouts due to thermal protection.
- **Fix:** We adjusted the PWM frequency to optimize efficiency and added larger heatsinks to the L298N modules. For the next iteration, we are evaluating more efficient drivers like the DRV8833 or a dedicated brushless motor setup.
- **Issue:** The ultrasonic sensor readings were highly erratic when the motors were running due to electrical noise.
- **Fix:** Implemented software debouncing and oversampling (reading 10 samples and taking the median) to stabilize the readings. Physical shielding of the sensor wires is planned for the next sprint to mitigate the underlying noise source.

**Next Steps:**
- Integrate the MPU6050 IMU for pitch/roll correction and heading stabilization.
- Begin development of the high-level navigation logic (path planning and obstacle avoidance) on the Raspberry Pi 4, utilizing the sensor data provided by the Arduino.

## 🚀 Project Update - EnergySense IoT Monitor

**Date:** 2026-03-30

**Progress:**
- Completed hardware assembly and initial firmware development for the prototype energy monitoring unit.
- Successfully established communication between the ESP32 microcontroller and the MQTT broker (Mosquitto) for real-time data streaming.

**Technical Work:**
- **Sensor Calibration:** Calibrated the SCT-013 non-invasive current sensors against a known load (heater). Developed a calibration function to convert raw ADC readings from the ESP32 to accurate RMS current values (Irms).
- **MQTT Implementation:** Configured the ESP32 using the PubSubClient library to connect to the local Mosquitto broker. Data points (current, voltage, power factor) are packaged as JSON objects and published to specific topics (e.g., `house/energy/circuit1`).
- **Low-Power Mode:** Implemented deep sleep functionality on the ESP32. The device now sleeps for 5 minutes between readings to minimize power consumption, waking up via a timer interrupt. This significantly extends battery life for potential remote deployment.

**Issues & Fixes:**
- **Issue:** Initial power consumption was too high, draining the battery prototype quickly. The Wi-Fi module on the ESP32 was drawing significant current even when inactive.
- **Fix:** Refactored the Wi-Fi connection logic to only connect to the network, publish the data, and immediately disconnect before entering deep sleep. This reduced average current draw by over 80%.
- **Issue:** The ADC readings from the SCT-013 sensors showed significant jitter, particularly during periods of low current draw.
- **Fix:** Implemented oversampling and digital filtering in the firmware (specifically, a simple moving average filter) to smooth out readings before performing the RMS calculation.

**Next Steps:**
- Begin work on the data visualization dashboard using Node-RED to display real-time and historical power usage.
- Design and fabricate a custom enclosure for the prototype unit.
- Conduct long-term stability testing to ensure reliable data reporting over several days.

## 🚀 Project Update - Vision_QD (AI Defect Detection)

**Date:** 2026-03-30

**Progress:**
- Completed the initial training run for the defect detection model (YOLOv5 implementation).
- Achieved promising results on the validation set for detecting major surface defects on manufactured parts.
- Deployed a test version of the model to a Jetson Nano for edge inference benchmarking.

**Technical Work:**
- **Dataset Preparation:** Labeled approximately 5,000 images using CVAT, categorizing defects into three classes: 'scratch', 'dent', and 'discoloration'. Implemented data augmentation (rotation, brightness adjustment) to expand the dataset.
- **Model Training:** Trained a YOLOv5s model on a T4 GPU using a batch size of 16 for 100 epochs. Monitored mAP@0.5 and F1 score during training. Achieved mAP@0.5 of 0.82 on the validation set.
- **Edge Deployment:** Converted the PyTorch model to ONNX format and then to TensorRT for optimized inference on the Jetson Nano. Set up the camera streaming pipeline using GStreamer.

**Issues & Fixes:**
- **Issue:** The model showed poor recall for the 'discoloration' defect class. Upon review, the dataset exhibited significant class imbalance, with 'scratch' and 'dent' defects being far more prevalent in the training data.
- **Fix:** Implemented weighted sampling during training to prioritize 'discoloration' samples. This improved recall for the minority class at the cost of a slight decrease in overall precision. Further balancing via additional data collection for the minority class is planned.
- **Issue:** Inference time on the Jetson Nano was initially too slow (over 500ms per frame) for real-time application (target <100ms).
- **Fix:** TensorRT conversion improved inference significantly (to ~150ms), but further optimization is needed. We are exploring quantization (INT8) of the model weights to reduce computation time.

**Next Steps:**
- Perform additional data collection to balance the dataset.
- Refine the TensorRT optimization pipeline, focusing on INT8 quantization.
- Develop the user interface (UI) on the Jetson Nano for real-time defect visualization and logging.
