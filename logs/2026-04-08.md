## 🚀 Project Update - Autonomous Mobile Robot (AMR) Platform

**Date:** 2026-04-08

**Progress:**
- Completed initial integration and tuning of the differential drive system.
- Successfully implemented basic open-loop motor control and verified mechanical constraints.
- Began development of the odometry system using quadrature encoders and sensor fusion.

**Technical Work:**
- **Motor Control System:** Integrated two 12V DC gearmotors controlled by DRV8833 motor drivers via a custom PCB breakout board. Initial tuning of the PID controller (P gain = 0.5, I gain = 0.01, D gain = 0.05) to achieve stable speed control.
- **Odometry Implementation:** Wrote C++ code on the STM32F4 microcontroller to capture quadrature encoder pulses using timer interrupts. Implemented a basic odometry calculation function that estimates position (x, y, theta) based on wheel rotations.
- **Sensor Integration:** Began testing the BNO055 IMU for drift compensation. Initial results show significant drift over time, requiring further filtering (Kalman filter implementation) to accurately fuse encoder and IMU data.

**Issues & Fixes:**
- **Issue:** Observed significant odometry drift (up to 10% error over a 5-meter run) when relying solely on encoder data, especially during turns where wheel slippage is prominent.
- **Fix:** Implemented a complementary filter to fuse IMU yaw data with encoder-derived heading. This reduced short-term drift but highlighted a new challenge: compensating for magnetic interference from the motors on the BNO055 sensor. Further shielding or calibration required.

**Next Steps:**
- Implement a robust Kalman filter for sensor fusion (encoders + IMU).
- Integrate the LiDAR sensor (RPLIDAR S1) for real-time localization and obstacle avoidance.
- Begin development of the high-level path planning module (A* algorithm) on the companion Raspberry Pi 4.

## 🚀 Project Update - Smart Hydroponics Monitor (SHM) System

**Date:** 2026-04-15

**Progress:**
- Completed hardware assembly and testing of the sensor array.
- Successfully established reliable data transmission to the cloud platform (AWS IoT Core).
- Began development of the power management module for battery-powered deployment.

**Technical Work:**
- **Sensor Array Integration:** Integrated and calibrated multiple sensors on the ESP32 WROOM module.
    - **pH Sensor:** Calibrated the analog pH probe (BNC connector) using a two-point calibration method (pH 4.0 and pH 7.0 buffer solutions). Implemented code to convert ADC values to pH readings.
    - **Temp/Humidity Sensor:** Integrated the BME280 sensor via I2C. Wrote a custom I2C library to ensure stable readings from multiple sensors on the same bus.
- **Cloud Communication:** Configured the ESP32 to connect to a local WiFi network and establish an MQTT connection to AWS IoT Core. Implemented JSON payload generation to send sensor data efficiently every 10 minutes.

**Issues & Fixes:**
- **Issue:** Intermittent "ghost" readings from the pH probe. The analog readings would fluctuate wildly, sometimes reporting values far outside the valid range (0-14 pH).
- **Fix:** Identified the issue as electrical noise on the analog input line. Added a 0.1uF capacitor across the VCC and GND pins of the pH breakout board and implemented digital filtering (averaging the last 10 readings) in the firmware. This significantly stabilized the readings.
- **Issue:** Occasional network disconnections (MQTT timeouts) when the ESP32 was left running for extended periods.
- **Fix:** Implemented a robust reconnection logic using the ESP32's built-in WiFi event handling and watchdog timer to automatically re-establish the MQTT connection upon failure.

**Next Steps:**
- Implement deep sleep functionality to reduce power consumption for battery operation.
- Develop a basic web-based dashboard using AWS Lambda and DynamoDB to visualize the incoming sensor data.

## 🚀 Project Update - Edge AI Object Detection Pipeline

**Date:** 2026-04-22

**Progress:**
- Completed dataset annotation and preparation for the custom object detection model.
- Successfully trained an initial prototype model (YOLOv5s) on the prepared dataset.
- Began evaluating model performance on different edge hardware (Raspberry Pi 4 vs. Jetson Nano).

**Technical Work:**
- **Dataset Preparation:** Annotated 1,500 images using Roboflow for two custom classes ("defect_A" and "defect_B") relevant to the quality control task. Ensured a balanced distribution of images across different lighting conditions and angles.
- **Model Training:** Trained YOLOv5s using PyTorch on a cloud GPU instance (V100). Achieved an initial mAP@0.5 of 0.82 after 100 epochs. Exported the model weights in ONNX format for deployment flexibility.
- **Quantization Testing:** Experimented with post-training quantization (int8) using TensorFlow Lite to reduce model size and improve inference speed on the Raspberry Pi 4.

**Issues & Fixes:**
- **Issue:** Significant accuracy degradation (mAP dropped to 0.65) after applying int8 quantization. The model struggled to correctly identify smaller objects in the dataset.
- **Fix:** Adjusted the quantization strategy from full int8 to dynamic range quantization. This provided a better balance between accuracy and performance on the resource-constrained hardware. Also investigated model pruning techniques, but initial tests did not yield significant performance gains without further accuracy loss.
- **Issue:** Inference speed on the Raspberry Pi 4 was too slow (approx. 2.5 FPS) for real-time application requirements (target: 10 FPS).
- **Fix:** Optimized the input preprocessing pipeline and utilized the `tflite_runtime` library directly rather than a high-level framework. Further optimization will involve exploring hardware acceleration options (e.g., Coral Edge TPU).

**Next Steps:**
- Finalize model optimization for edge deployment (Jetson Nano) by leveraging NVIDIA TensorRT.
- Develop a Python script for real-time inference using a USB camera input on the edge device.
- Create a simple dashboard to visualize detection results and performance metrics.
