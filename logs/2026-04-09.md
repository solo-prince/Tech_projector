## 🚀 Project Update - Autonomous Logistics Rover (ALR-1)

**Date:** 2026-04-09

**Progress:**
- Completed initial integration and tuning of the DC motor PID control loop for precise speed regulation.
- Successfully implemented basic open-loop odometry calculation based on encoder ticks.
- Designed and fabricated a custom sensor mount for the ultrasonic rangefinders.

**Technical Work:**
- **PID Tuning:** Implemented a PID controller on the Arduino Mega to manage motor speed. The motor encoders provide real-time feedback (ticks per second), which is compared to the target speed. Initial tuning focused on stabilizing the P and I terms. Found a stable configuration at P=0.8, I=0.05, D=0.01 after significant oscillation testing.
- **Odometry:** Wrote code to calculate the rover's position by integrating encoder data. The logic accounts for wheel diameter and track width to estimate distance traveled and heading change. Current implementation has significant drift due to wheel slip, which will be addressed in future steps with IMU integration.
- **Hardware Integration:** Configured all four motor drivers (DRV8833) and tested communication protocols (PWM/DIR signals).

**Issues & Fixes:**
- **Issue:** High-frequency electrical noise from the motor drivers was causing intermittent data corruption on the I2C bus during encoder readings, leading to unstable PID output.
- **Fix:** Added 100nF decoupling capacitors directly across the power rails of the encoder modules. Also implemented a software moving average filter (window size 5) on the encoder readings to smooth out high-frequency spikes before feeding data into the PID loop. This significantly improved stability.

**Next Steps:**
- Integrate the IMU (BNO055) to provide reliable heading information for better odometry calculation.
- Implement sensor fusion between odometry (encoders) and IMU data using an Extended Kalman Filter (EKF) to reduce drift and improve localization accuracy.
- Begin development of the path planning algorithm (e.g., A* or Dijkstra's) for autonomous navigation.

## 🚀 Project Update - Smart Hydroponics Monitor (AutoGrow V2)

**Date:** 2026-04-16

**Progress:**
- Completed integration of all environmental sensors (pH, EC, DS18B20 temperature probe).
- Developed and tested the data acquisition and transmission logic on the ESP32 platform.
- Implemented persistent storage (SPIFFS) for sensor calibration data.

**Technical Work:**
- **Sensor Polling:** Configured the ESP32 to poll pH and EC sensors. The pH sensor requires careful analog reading and voltage conversion. The EC sensor uses an AC excitation method to prevent polarization, which was implemented with a custom library.
- **Data Transmission:** Established an MQTT connection to a cloud broker (AWS IoT Core). The ESP32 publishes sensor readings in JSON format every 5 minutes. Implemented connection resilience logic, including automatic reconnection and data buffering if the Wi-Fi connection drops.
- **Calibration Routine:** Developed a user-driven calibration routine for the pH sensor (two-point calibration using pH 4.0 and 7.0 solutions). The calibration values are stored in SPIFFS and loaded at boot time to ensure accuracy.

**Issues & Fixes:**
- **Issue:** Intermittent "ghost" readings where pH values would temporarily spike to extreme high or low values during data acquisition.
- **Fix:** Traced the issue to electrical interference from the peristaltic pump's motor, which was sharing the same power rail as the sensor circuitry. Isolated the power supply for the pump and added a ferrite bead to the sensor's signal cable. This eliminated the noise spikes.

**Next Steps:**
- Integrate automated nutrient dosing logic (peristaltic pumps) based on real-time EC sensor readings. Develop logic to maintain target EC levels autonomously.
- Create a simple web interface on the ESP32 (AP mode) for local configuration and status monitoring.

## 🚀 Project Update - Edge AI Anomaly Detection (Project Sentinel)

**Date:** 2026-04-23

**Progress:**
- Successfully trained and fine-tuned a new object detection model (YOLOv8) on the custom dataset.
- Completed model quantization (int8) and deployment to the NVIDIA Jetson Nano.
- Achieved stable real-time inference at 15 FPS on target hardware.

**Technical Work:**
- **Model Training:** Refined the custom dataset by adding more negative samples (background images without objects) to improve robustness against false positives. Trained YOLOv8 using transfer learning from a pre-trained COCO model. Achieved a mean Average Precision (mAP) of 91.2% on the validation set.
- **Quantization:** Performed post-training quantization (int8) using the TensorRT framework on the Jetson Nano. This process converts the model weights from floating-point (FP32) to 8-bit integers, significantly reducing model size and latency.
- **Deployment Pipeline:** Integrated the quantized model into a C++ inference pipeline using the Jetson Nano's libraries. This pipeline handles real-time video stream input, pre-processing, model inference, and results visualization (bounding boxes).

**Issues & Fixes:**
- **Issue:** Initial deployment of the full FP32 model resulted in unacceptably high latency (3-4 FPS) on the Jetson Nano, making real-time processing impossible. The CPU utilization was spiking, indicating a bottleneck in the pre-processing steps.
- **Fix:** The bottleneck was identified in the image resizing and color space conversion steps. Optimized the pre-processing using OpenCV's GPU acceleration features (cuda::resize and cuda::cvtColor) before feeding the data to the TensorRT engine. The int8 quantization reduced the model size by ~70%, further improving throughput to 15 FPS.

**Next Steps:**
- Integrate the inference results with the physical automation system. Trigger specific actions (e.g., sound alarm, send notifications) based on detected anomalies.
- Develop a mechanism for model updates and over-the-air deployment (OTA) to simplify future model iterations.
