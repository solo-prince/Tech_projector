## 🚀 Project Update - OmniDrive Robotics Platform

**Date:** 2026-04-05

**Progress:**
- Completed initial integration and calibration of the four-wheel omnidirectional drive system.
- Successfully implemented basic open-loop control for forward/reverse movement and rotation.
- Began development of closed-loop velocity control using PID feedback from motor encoders.

**Technical Work:**
- **Hardware:** Assembled the chassis (custom aluminum frame), integrated four DC gear motors with encoders, and installed the ESP32-S3 microcontroller and four-channel motor driver board (L298N replacement with integrated current sensing).
- **Firmware:** Developed core motor control code using PlatformIO. Implemented a timer interrupt routine (50ms interval) to read encoder pulses and update motor PWM signals based on the desired velocity.
- **PID Tuning:** Initial tuning for the P-term (Proportional gain) to stabilize velocity. Tested various P values to find the sweet spot between responsiveness and oscillation. The current P-gain of 0.8 significantly reduced velocity error when comparing target speed to actual speed over short distances.

**Issues & Fixes:**
- **Issue:** Motors exhibited significant oscillation (hunting) around the target velocity when using a simple P-controller with higher gain values (P > 1.0). The system repeatedly overshot the target speed and corrected too aggressively.
- **Fix:** Added a D-term (Derivative gain) to dampen the oscillations. Initial D-gain of 0.1 improved stability significantly, allowing the robot to reach a steady state velocity much faster without overshooting. Further fine-tuning of the I-term (Integral gain) is needed to eliminate steady-state error.

**Next Steps:**
- Implement the full PID loop for all four motors.
- Integrate IMU data (MPU6050) for heading correction and basic odometry calculations.
- Develop high-level navigation logic for path following using a web interface.

## 🚀 Project Update - SmartFarm IoT Node V2

**Date:** 2026-04-05

**Progress:**
- Completed prototype testing for power optimization and deep sleep functionality.
- Successfully integrated multiple sensors (soil moisture, temperature/humidity) onto a single low-power board.
- Validated data transmission reliability over LoRaWAN network in a field environment.

**Technical Work:**
- **Hardware:** Migrated from ESP8266 to ESP32-S2 for improved power management capabilities and built-in LoRa support. Used a BME280 sensor for environmental data and a capacitive soil moisture sensor.
- **Firmware:** Developed a state machine to manage sensor acquisition, deep sleep cycles, and network transmission. The node now wakes up every 15 minutes, reads all sensor data, sends a single LoRa packet, and returns to deep sleep.
- **Power Optimization:** Optimized code to minimize wake time (less than 5 seconds per cycle) and disabled non-essential peripherals (WiFi, BLE) before entering deep sleep. Measured average current draw during sleep at ~15 µA.

**Issues & Fixes:**
- **Issue:** The capacitive soil moisture sensor exhibited inconsistent readings due to voltage fluctuations during the startup sequence. The sensor required a stable VCC reference.
- **Fix:** Implemented a dedicated power control pin (digital output) to apply power to the sensor only during the brief acquisition window. This prevented voltage sag during the initial power-on cycle and stabilized readings.

**Next Steps:**
- Design a custom PCB to replace the breadboard prototype, integrating power circuitry (solar charging, battery management).
- Integrate a simple local display (e-paper) to show current readings when near the node.
- Deploy a small mesh network (3 nodes) for long-term field testing and data collection.

## 🚀 Project Update - Edge Gesture Recognition Model

**Date:** 2026-04-05

**Progress:**
- Completed data collection and labeling for three core gestures (swipe left, swipe right, hold still) using the target hardware (Arduino Nano 33 BLE Sense).
- Trained the initial Convolutional Neural Network (CNN) model using TensorFlow Lite for Microcontrollers (TFLite Micro) pipeline.
- Achieved initial validation accuracy of ~85% on the test dataset.

**Technical Work:**
- **Data Collection:** Captured 10-second sequences of raw IMU (accelerometer and gyroscope) data for each gesture. Used a custom Python script running on the host PC to receive data via serial port and label it.
- **Model Training:** Designed a small 1D CNN architecture suitable for edge deployment. The model consists of two convolution layers followed by pooling and a final dense layer. Trained the model for 50 epochs on the collected dataset.
- **Model Quantization:** Applied post-training quantization to reduce the model size from floating-point (FP32) to 8-bit integers (INT8). The model size shrank from ~300 KB to ~75 KB, which fits within the memory constraints of the target device.

**Issues & Fixes:**
- **Issue:** The initial model exhibited high accuracy (95%+) on the training set but significantly lower accuracy (70%) on the validation set, indicating overfitting. The model was learning noise specific to individual data collection runs.
- **Fix:** Implemented data augmentation techniques, including adding small amounts of Gaussian noise and time-warping the sensor data during training. This forced the model to learn more general features, improving validation accuracy to 85% and significantly reducing overfitting.

**Next Steps:**
- Deploy the quantized TFLite model onto the Arduino Nano 33 BLE Sense using the TFLite Micro library.
- Develop the inference code on the embedded device to perform real-time gesture detection.
- Optimize the model further for latency and explore alternative architectures (e.g., RNN) for comparison.
