## 🚀 Project Update - AetherBot Navigation Stack

**Date:** 2026-04-03

**Progress:**
We successfully completed the initial integration and testing of the core navigation stack components. The robot can now execute basic movement commands (move forward X distance, turn Y degrees) and maintain position hold using sensor fusion. We've moved from basic open-loop control to closed-loop feedback using wheel encoders and IMU data.

**Technical Work:**
*   **Odometry Implementation:** Integrated the quadrature encoders on the left and right motors. Implemented interrupt-driven counting on the Teensy 4.0 microcontroller. Calculated wheel velocity and distance traveled based on encoder ticks per revolution and wheel circumference.
*   **Sensor Fusion:** Implemented a complementary filter (initial testing of Kalman filter also started) to combine data from the MPU6050 IMU (specifically, angular velocity from the gyroscope) and the wheel encoders (for linear distance and estimated angle change). This significantly reduces the drift inherent in both individual sensor types. The filter prioritizes encoder data for linear displacement over short distances but relies on IMU data for angle correction to compensate for wheel slippage during turns.
*   **PID Control Tuning:** Began initial tuning of the velocity PID controllers for each motor. The P gain was set to provide quick response, while the D gain was introduced to dampen oscillations at higher speeds. The I term is currently disabled during initial tests to avoid windup.

**Issues & Fixes:**
*   **Issue:** Significant "odometry drift" when executing long linear movements on varying surfaces. The calculated distance from the encoders consistently overestimates the actual distance traveled, likely due to wheel slip on non-ideal surfaces (e.g., carpet vs. smooth vinyl).
*   **Fix:** Increased the weight of the encoder data in the complementary filter for linear displacement calculations during straight-line travel. For turning maneuvers, where wheel slip is more pronounced, we rely more heavily on the IMU's angular velocity data to determine the actual angle of rotation. We also introduced a calibration routine to measure the actual distance traveled versus the encoder count over a 2-meter run to derive a more accurate conversion factor.

**Next Steps:**
*   **Obstacle Avoidance Integration:** Integrate the TFMini Plus LiDAR sensor for real-time distance measurement and obstacle detection.
*   **Path Planning:** Develop a simple path planning algorithm (e.g., A* or Dijkstra's) to combine navigation commands with obstacle avoidance inputs.
*   **Refine PID Tuning:** Further optimize PID parameters for smooth acceleration/deceleration profiles and minimize overshoot during stopping.
